# Gate 3 失败假设：裁片 OCR 的完整字符仍可能是跨框整词的残片

## 观察

`hypothesis-run-09` 已将框外原文限制在邻接 OCR 清单内；最终框内白名单保留了 `0`、`159`。精确裁片显示它们分别来自完整值 `0.0%`、`159.9%`，字符自身未触及裁片边缘，但完整词多边形跨越红框右边界。

## 可证伪假设

转写资格应由完整截图 OCR 的整词几何决定。只有完整词多边形完全落入目标框，才进入 `complete_text_tokens`；裁片 OCR 仅作为诊断。应用此规则后，当前走廊的框内 token 清单会从 `0, 159` 变为空，最终建议只能描述纹理和线条。

## 重跑判据

- manifest 区分裁片 OCR 诊断结果与完整截图整词白名单。
- 完整值多边形跨边界时，其任何裁片前后缀都不能进入白名单。
- 当前最终 `visible_text_tokens=[]`、`adjacent_text_tokens=[]`，`visible_cue` 无任何 UI 原文或数值。
