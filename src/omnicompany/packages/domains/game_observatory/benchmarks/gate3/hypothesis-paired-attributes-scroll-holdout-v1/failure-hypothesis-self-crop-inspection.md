# Gate 3 失败假设：模型没有看到自己画出的精确目标框

## 观察

`hypothesis-run-05` 已满足确定性几何和来源合同。120 像素宽的走廊只覆盖属性表中部的浅色纹理与分隔线，模型仍把框外两侧的属性名和数值写成框内线索。

## 可证伪假设

只有完整截图和坐标网格时，语言模型会在心理上把目标框等同于整个控件。若在最终提交前把候选框渲染为“上下文红框 + 精确目标像素”并真实送入下一轮，且运行时要求最终框与已查看裁片逐值一致，模型会把 visible cue 限定在实际框内像素，或主动调整框后重新检查。

## 改进与重跑判据

- 新增 `inspect_probe_region`，只生成内部检查图，不操作设备。
- 最终提案必须带当前 session 的 `region_inspection_id`，框与检查记录完全一致，裁片已真实送达。
- `visible_cue` 不再把裁片外文字或数值写成框内内容。
- 该机制同时适用于后续 tap 与 swipe 提案。
