# Gate 3 失败假设：既有事实结果被语言模型扩写

## 观察

`hypothesis-run-01` 正确复制了既有 swipe 起止点，并将动作绑定到当前英雄属性列表；`expected_change` 在既有事实“显示更下方属性条目”后加入了“穿透、吸血”等具体例子。

## 可证伪假设

提示词里的“不得扩展结果含义”不足以约束生成。若把既有事实引用、动作几何和 `expected_change` 的逐字段一致性提升为 `propose_probe` 运行时合同，同一冻结输入会先拒绝扩写版本，最终账本只保留与既有事实一致的提案。

## 改进与重跑判据

- 既有事实精确模式要求显式 `prior_fact_id`。
- `target_name`、`action_type`、已知动作几何、已知目标框与 `expected_change` 必须和引用事实一致。
- 账本保留 `prior_fact_id`，便于外部裁决追溯。
- 同一留出图重跑后，账本中不得出现未由当前画面或既有事实支持的具体后续属性名。
