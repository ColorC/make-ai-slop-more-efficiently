# 00 · 本体自述

本手册是 omnicompany 自管决策本体的语义层:一本互相引用的文档,所有软判断用文字写明。四个原语:**陈述**(载体=决策库 records.jsonl,本手册条目=其中蒸馏态)、**运行**(事件流,带消费留痕)、**投影**(接口文件/检查单/视图,皆可重建)、**候选**(一切改库提议,统一排队人裁)。

陈述的机器契约=`src/omnicompany/packages/domains/decisions/formats.py DECISION_RECORD`(三轴:nature 规范/事实、status 生效状态、authority 权威与出处;蒸馏态=distilled+book_ref;when 两小节=trigger/holds_when;版本不可变递增 version+fold 最新行为「当前生效」;偏离豁免=deviation_waiver;验证件=verification;投影列表=projections;被否项生命周期=decision_space[].ruling/promote_when)。本手册不复述字段细节,以该文件为机器权威。

北极星:**被真实使用**。任何条目、机制若长期无消费留痕,进退役复核,不留摆设。

## 条目模板(每个条目照此结构,缺项显式写"暂缺")

```
## <条目名>
结论:一句话。
什么时候:
  注入/触发:什么情境该被调出(文字语义描述;可选硬匹配键;判断类型=规则/统计/大模型)。
  成立情境:这条结论在什么给定条件下成立。
判断怎么下:软判断全文——考虑什么、权衡什么、什么算好、边界案例怎么想。
谁拍板:角色与权威等级;推翻条件(什么情况下本条要重审)。
判例:决策库真 id 列表(DEC-/BLF-)。
验证件:黄金场景/机检脚本(挂现有评测设施,暂缺则写暂缺)。
投影:消费方列表,带类型(hook/skill/CLAUDE.md/管线),只列指针。
规模与接入:指向管线注册表(机器真源),条目不复述数值。
```

## 治理规则

1. **唯一写入通道=候选流水线**:偏离聚集、固化聚类、到期信号、AI 记忆、外部建议,一律先成候选、审阅台人裁后才写入;人与 AI 提交同门,只差发起者字段。"报告偏离"与"提议修订"是两个动作,任何自动回路不得直改本手册。
2. **版本与指针**:条目版本不可变递增;"当前生效"是可变指针;被推翻作废不删除,保留取代链与判例引用。改版先过验证件(有验证件的条目)。
3. **接口只存指针**:一切从本手册摘出的内容,落到 hook/skill/CLAUDE.md 时必须带 `<!-- Source: docs/ontology/<文件>#<条目> -->` 注释;接口漂移检查=重放生成+比对。
4. **检查单纪律**:派生检查单每节 5-9 条,超限拆分;扫描单(防漏看)与操作单(照做)分开;不承诺"照做全对",需临场判断处显式标注。
5. **冲突优先序**:亮线(hook 机检)> 常驻原则 > 手册条目 > 判例惯例;同级后法优于前法、特别优于一般;仍裁不了则显式悬置报人,禁止静默选边。
6. **升级人裁判据**:新情况与判例库一致→自动走;两种结论都不矛盾→执行者自由裁量(记录即可);真冲突→惊动用户。
7. **边词表**:陈述间关系用动词六词表(拆分/推导/联想/生成/反证/延伸)为正典;推导必须 rests_on 指回前提,证伪沿链传播。机器映射=`domains/decisions/verbs.py REL_TO_VERB`(links/因果边/被否项边全部映射进六词,旧 rel 保留为机器键兼容读);禁止新增第三套词表,新 rel 映射不进六词=先回手册裁决。
8. **规范与事实分区**:规范性条目(该怎么做)与事实性陈述(世界是怎样,即假设/知识)同库不同轴;事实性陈述晋升前必须过挑战(challenge),高风险假设之上不搭长推导链。
9. **通则即条目**:探索通则、写作通则等一切"通则"都是普通条目,无特殊机制。
10. **不完备为前提**:低频异质的判断显式标"留作临场判断";品味核心存参照样例,不硬编假规则。
11. **收录范围(2026-07-10 用户界定)**:只收决策类知识。日常工作的性价比考虑与环境约束类规则(预算控制如禁 fable 工人、机器限制等)不收,留在接口层原地——它们与决策差距甚远,强行收编是垃圾制造。
12. **清场纪律(2026-07-10 用户令)**:任何收编、合并、瘦身动作必须以拆除步收尾——迁移→改引→拆除旧物(删除或归档到指定位置)→巡检确认零残留;不完成拆除不算完成;不留双轨长尾;废弃物归档不散落;巡检常项含"旧路径仍被引用/旧文件仍存在"的废墟检测(机器件=`omni decisions patrol` + guardian OMNI-101)。
13. **规范文档渐进指针化(合并清单#6/#7,长期纪律非一次工程)**:docs/standards 与各 DESIGN.md 里的**判断类**内容(为什么这么定、权衡了什么),在该文档下次被实质修改时顺手补陈述指针——正文旁标 `(判例: DEC-...)` 或把拍板记进库后引 id;纯说明书部分(怎么操作、参数表)留原地不动。不做批量搬迁(明确不做清单);新立规范文档从第一天就带判例 id。
14. **裁决渠道(2026-07-10 用户定则)**:待裁决问题在对话内直接提出并由用户在对话内答复,答复原话记 anchor;审阅台是次要路径——主用于"看"(只收工作报告/对照稿类材料,禁把裸的待裁问题单独作为材料推上去),次用于明确需要交叉裁决的项目;材料的 accept/reject 状态不作为用户同意与否的判据,除非附有较明确的用户评论。候选流水线仍是唯一写入通道(登记与留痕),但"人裁"信号以对话内答复为主渠道。判例:DEC-2026-07-10-059。
