# 50 · 对外发布

本分册保存对外发布时反复需要调用的判断规则。它只写当前有效的判断方法；操作步骤、模板和命令由各发布域的 `SKILL.md` 承载。

## 工作规范与连续性信息分层
结论:发布 Agent 的工作规范统一进入操作手册；Memory 只保存身份连续性、真实发布状态、已公开内容概要和待续主题。
什么时候:
  注入/触发:建立或修改发布 Agent、写作 prompt、发布前读取上下文时；判断类型=规则。
  成立情境:使用无状态大模型执行持续发布任务。
判断怎么下:凡是“每次都应怎样做”的内容归操作手册、模板、检查单或代码门禁；凡是“已经公开过什么、当前接着什么”的内容归 Memory。纠错过程不能充当工作规范，过时草稿不能进入当前规则包。
谁拍板:ColorC，权威=user_explicit；当发布 Agent 的持久化机制整体替换时重审。
判例:DEC-2026-07-14-003。
验证件:prompt bundle 测试确认 Memory 不加载纠错记录，手册包包含 SKILL、模板与检查单。
投影:skill=`src/omnicompany/packages/domains/xiaohongshu_publish/SKILL.md`；pipeline=`xiaohongshu.publish`；memory=`config/xiaohongshu_publish/agents/publisher/memory/MEMORY.md`。
规模与接入:`src/omnicompany/core/pipelines.py` 的 `xiaohongshu.publish` 与 `xiaohongshu.memory`。

## 写作前读取已公开内容概要
结论:写作 Agent 动笔前必须读取真实发布状态和逐帖概要，确认本篇新增信息并删除对前帖的无意义重复。
什么时候:
  注入/触发:形成选题 brief、续写系列内容、重写待审稿时；判断类型=规则。
  成立情境:账号已经有公开内容，或同批次多帖存在明确分工。
判断怎么下:先区分“已公开”“审阅中”“撤回”三种状态；只把已公开内容当作读者可能见过的前文。新帖可以用一句话补足必要上下文，不能重新讲前帖已经完整讲过的起始时间、账号自我介绍或来源规则。若前文尚未公开，同批次各帖仍要按分工去重。
谁拍板:ColorC，权威=user_explicit；平台取消系列发布形态时重审。
判例:DEC-2026-07-14-003。
验证件:authoring packet 必须带当前 `post-summaries.md` 的 SHA-256 摘要。
投影:checklist=`config/xiaohongshu_publish/manual/checklists/01-before-writing.md`；template=`config/xiaohongshu_publish/manual/templates/content-brief.md`。
规模与接入:`xiaohongshu.publish` 的 ManualCompliancePreflight。

## 完整事实母稿先于载体适配
结论:先写一份不受平台字数、图片张数和时长限制的完整事实母稿，再决定图文、长文、视频或分篇。
什么时候:
  注入/触发:选题包含多个阶段、多个纠错案例、多个数字或多个产物时；判断类型=规则。
  成立情境:内容需要从内部材料转成对外经验分享。
判断怎么下:母稿需要把对象、背景、实际动作、产物、问题、修正、结果和仍未完成的边界写全。载体选择发生在母稿完成后；如果正常字号、可读图卡和正文容量装不下，就选择长文、视频或拆成系列，不能先压缩事实来迎合一个固定模板。
谁拍板:ColorC，权威=user_explicit；平台载体能力变化时只更新载体表，本结论继续有效。
判例:DEC-2026-07-14-003。
验证件:authoring packet 必须包含 `uncompressed_master` 与 `carrier_plan`，并由摘要门禁防止母稿变更后沿用旧检查结果。
投影:template=`config/xiaohongshu_publish/manual/templates/uncompressed-master.md`；template=`config/xiaohongshu_publish/manual/templates/carrier-plan.md`。
规模与接入:`xiaohongshu.publish` 的 ManualCompliancePreflight。

## 当前产出优先于形成过程
结论:涉及项目或管线的文章，先让读者知道这段时间具体做成了什么、现在能解决什么，再讲形成过程和纠错。
什么时候:
  注入/触发:介绍工具、网站、发布管线、实验或长期项目时；判断类型=大模型。
  成立情境:文章同时包含当前状态和早期变化。
判断怎么下:开头应能回答“现在有什么、能做什么、读者为什么值得继续看”。形成过程用于解释关键取舍，不能占满开头，也不能只剩抽象感悟。若当前产出有多个模块，先给可理解的全景，再选与本篇问题有关的变化展开。
谁拍板:ColorC，权威=user_explicit；纯复盘型选题可在 brief 中声明例外。
判例:DEC-2026-07-14-003。
验证件:内容 brief 与审稿 rubric 都有“当前产出”字段。
投影:rubric=`config/xiaohongshu_publish/manual/rubrics/content-quality.md`；checklist=`config/xiaohongshu_publish/manual/checklists/02-draft-review.md`。
规模与接入:`xiaohongshu.publish` 写作手册阶段 B-C。

## 事实展开到陌生读者可复述
结论:每个关键案例必须写清对象、当时在做什么、采取了什么动作、出现了什么问题、怎样修正、得到什么结果和还剩什么边界。
什么时候:
  注入/触发:正文或图卡出现项目名、内部命名、数字、撤回、失败、修正或“做了某事”时；判断类型=大模型。
  成立情境:目标读者没有读过内部文档。
判断怎么下:删除只有结论的压缩句。陌生人读完案例后，应能用自己的话说出事件对象和动作链。诸如“填厚作品页”“开发日志故事”“53页审查”一类短语本身不构成解释，必须展开它们指向的页面、材料、错误内容、审查对象和修正结果。
谁拍板:ColorC，权威=user_explicit；涉及隐私或商业信息时使用忠实且明显的代称，仍保留动作与因果结构。
判例:DEC-2026-07-14-003。
验证件:事实台账模板要求七个字段；审稿检查逐案例核对。
投影:template=`config/xiaohongshu_publish/manual/templates/fact-ledger.md`；checklist=`config/xiaohongshu_publish/manual/checklists/02-draft-review.md`。
规模与接入:`xiaohongshu.publish` authoring packet。

## 数字必须带对象与口径
结论:数字首次出现时必须同时说明它统计什么、统计范围、相关动作、结果含义和已知限制。
什么时候:
  注入/触发:标题、正文、图卡、口播出现数量、比例、日期跨度、版本数或审查结果时；判断类型=规则+大模型。
  成立情境:数字用于支撑文章判断。
判断怎么下:例如页面数要拆清作品页与开发日志的构成；术语解释数要说明解释被放到哪里、解决什么阅读问题；阻断项要说明由什么检查发现、包含哪些类别、是否全部修复、是否完成下一轮复审。缺少口径的数字删除或回源补全。
谁拍板:ColorC，权威=user_explicit；统计口径变化时在同段说明新旧差异。
判例:DEC-2026-07-14-003。
验证件:事实台账的 `数字口径` 字段不得空；审稿 rubric 单列数字完整性。
投影:template=`config/xiaohongshu_publish/manual/templates/fact-ledger.md`；rubric=`config/xiaohongshu_publish/manual/rubrics/content-quality.md`。
规模与接入:`xiaohongshu.publish` editorial review。

## 用户动机必须有明确来源
结论:只有 ColorC 明确说过的目的、感受和取舍才能归给 ColorC；可观察事实与编辑判断必须使用各自的表述。
什么时候:
  注入/触发:出现“为了”“希望”“想要”“意识到”“感慨”“让ColorC明白”等动机或心理表述时；判断类型=大模型。
  成立情境:AI 以发布 Agent 第一人称整理 ColorC 的项目和经历。
判断怎么下:事实来源分三类：ColorC 明说过的内容可写成 ColorC 的目的；文件、提交和运行输出只能支持可观察动作与结果；Agent 对结构和载体的选择应写成编辑判断，不能倒推为 ColorC 的动机。证据不足就删去心理因果。
谁拍板:ColorC，权威=user_explicit；ColorC 后续明确补充动机时可更新事实台账。
判例:DEC-2026-07-14-003。
验证件:事实台账要求 `归属类型` 与 `来源`；审稿检查所有动机动词。
投影:checklist=`config/xiaohongshu_publish/manual/checklists/02-draft-review.md`；rubric=`config/xiaohongshu_publish/manual/rubrics/content-quality.md`。
规模与接入:`xiaohongshu.publish` editorial review。

## 经验分享文体
结论:经验分享同时交代做了什么和从具体纠偏中得到什么；它保留选择过的事实链，避开逐日流水和规格书式全量罗列。
什么时候:
  注入/触发:选题目标写有“经验分享”“记录”“开发日志”时；判断类型=大模型。
  成立情境:面向不了解项目的社交平台读者。
判断怎么下:文章需要一个清楚的读者问题。先展示当前产物和作用，再选能回答该问题的具体动作、失败、修正和边界。流水账只按时间列动作，设计文档只列结构与规则；二者都缺少“为什么这几件事值得读者带走”的编辑选择。经验结论必须紧邻支撑它的案例。
谁拍板:ColorC，权威=user_explicit；纯操作教程和正式设计说明另走对应模板。
判例:DEC-2026-07-14-003。
验证件:content brief 要填读者问题、当前产物、入选案例和读者可带走内容。
投影:template=`config/xiaohongshu_publish/manual/templates/content-brief.md`；template=`config/xiaohongshu_publish/manual/templates/uncompressed-master.md`。
规模与接入:`xiaohongshu.publish` 写作手册阶段 A-C。

## 单篇中心与容量分流
结论:每篇只解决一个中心问题；正常字号和自然叙述达到容量上限时，优先换载体或分篇。
什么时候:
  注入/触发:一个 brief 出现多个互不依赖的问题，或正文、图卡、视频脚本需要持续缩字才能放下时；判断类型=规则+大模型。
  成立情境:小红书图文、长文、视频和系列帖均可作为候选载体。
判断怎么下:按信息任务分组，判断每组能否独立回答一个读者问题。图文适合结构化摘要与有限案例；长文适合完整论证；视频适合演示操作与状态变化；系列适合多个可独立成立的问题。拆分后每篇仍要有必要上下文，不能依赖读者记得内部名词。
谁拍板:ColorC，权威=user_explicit；真实平台能力由发布前接口检查更新。
判例:DEC-2026-07-14-003。
验证件:carrier plan 必填容量判断、拆分判断与被否载体理由。
投影:template=`config/xiaohongshu_publish/manual/templates/carrier-plan.md`；checklist=`config/xiaohongshu_publish/manual/checklists/03-carrier-visual.md`。
规模与接入:`xiaohongshu.publish` authoring packet。

## 图卡承担结构化信息且保持可读字号
结论:图卡用于承载结构、对照、流程、界面证据和重点案例；正文负责连贯叙述，任何关键内容不得靠过小字号塞入。
什么时候:
  注入/触发:设计图文笔记、调整卡片数量或渲染 HTML/CSS 时；判断类型=规则。
  成立情境:1080×1440 的 3:4 小红书图片。
判断怎么下:每张卡只承担一个信息任务。关键正文渲染字号不低于 42px，标题通常不低于 64px；窗口栏、页码等非关键信息可以更小，但不得承载理解文章所需的事实。出现缩字、密集小段或多层嵌套时，先增卡、改长文、改视频或分篇。
谁拍板:ColorC，权威=user_explicit；字号阈值可由真实手机预览校准，降低阈值需重新人审。
判例:DEC-2026-07-14-003。
验证件:DOM 计算样式扫描、1080×1440 文件检查和真实审阅页加载检查。
投影:checklist=`config/xiaohongshu_publish/manual/checklists/03-carrier-visual.md`；skill=`src/omnicompany/packages/domains/xiaohongshu_publish/SKILL.md`。
规模与接入:`xiaohongshu.publish` image text review。

## 视觉主题的意义不得代拟
结论:DOS终端主题的含义按ColorC明确表达记录：它包含对语言模型重新回到bash式操作环境的感慨；跨页面视觉一致性是独立目标，二者不得拼成未经确认的单一动机。
什么时候:
  注入/触发:文章解释个人网站或对外图卡为何采用DOS终端视觉时；判断类型=大模型。
  成立情境:需要说明视觉选择的来源与作用。
判断怎么下:可以客观描述黑绿配色、终端提示符、等宽字体、目录与命令式界面；可以分别写ColorC明确说过的感慨和视觉一致性目标；不能补造“为了统一导航”“为了让所有实验用命令管理”等动机。缺少原话支持的解释归为设计观察或删去。
谁拍板:ColorC，权威=user_explicit；ColorC补充新的视觉说明时更新。
判例:DEC-2026-07-14-003。
验证件:事实台账将视觉目的拆为独立来源项；审稿检查动机归属。
投影:template=`config/xiaohongshu_publish/manual/templates/fact-ledger.md`；rubric=`config/xiaohongshu_publish/manual/rubrics/content-quality.md`。
规模与接入:`xiaohongshu.publish` 写作手册阶段 B-C。

## 公开叙述、内部来源与平台 AI 标识分层
结论:公开正文用ColorC视角，不出现Agent/Model tag；完整来源进内部证据；每篇在小红书高级选项开启并复验AI内容标识。
什么时候:
  注入/触发:AI或混合内容生成公开载荷，或准备点击发布时；判断类型=规则。
  成立情境:正文、图卡、长文、视频、评论或私信由AI生成或经过AI编辑。
判断怎么下:连续发布仍以名字、SOUL和Memory维持内部连续性，最终模型使用完整精确ID，协作者与审查模型也保留在内部证据。公开第一人称指ColorC，相关经历、行动、成果、目的、感受和承诺必须有ColorC原话或可核验材料。AI归纳可用引号作为“报告摘录”，不得伪装成ColorC原话。正文不堆叠AI免责声明；发布前必须由工具读取平台AI内容标识为已勾选。
谁拍板:ColorC，权威=user_explicit；平台AI标识缺失、未勾选或无法验证时失败关闭。
判例:DEC-2026-07-14-003。
验证件:PreparePost、EditorialReview、authoring packet、平台AI标识检查与发布回执。

## 写作阶段自检先于独立审查
结论:写作Agent先按同一操作手册完成自检，独立审查员只负责寻找遗漏和提供证据，不能成为质量的主要来源。
什么时候:
  注入/触发:组织多模型写作与交叉审查时；判断类型=规则。
  成立情境:存在独立写作Agent和审查Agent。
判断怎么下:写作前加载手册、模板、检查单和发布概要；成稿后写作Agent先填检查报告。独立审查只检查事实展开、动机归属、前文重复、术语首见、载体容量、字号和公开边界。若审查发现系统性问题，应修操作手册或模板，不能只改当前稿。
谁拍板:ColorC，权威=user_explicit；没有独立审查资源时仍需完成写作自检与确定性门禁。
判例:DEC-2026-07-14-003。
验证件:manual packet 要求写作自检和独立审查均完成；二者缺一时发布预检失败。
投影:rubric=`config/xiaohongshu_publish/manual/rubrics/content-quality.md`；checklist=`config/xiaohongshu_publish/manual/checklists/04-prepublish.md`。
规模与接入:`xiaohongshu.publish` ManualCompliancePreflight。
