## 布局·真实元素纪律

结论:界面设计与概念图只收录游戏里真实存在的元素;向成熟游戏学习学的是布局尺寸手法,禁止把对方有而我们没有的交互/信息面搬进来;仪式锚点(大圆章类)不能脱离真实功能凭形式感发明。
什么时候:
  注入/触发:画布局图、写生成 prompt、评审概念图时;判断类型=规则(逐元素对照真实界面)+大模型(识别虚构面)。
  成立情境:2026-07-10 用户两次否决后长期有效(walker 全界面通用)。
判断怎么下:对图上每个元素问"游戏里现在有没有这个信息源/这个操作"——没有就删(判例:右侧「战况」大圆章无对应功能、顶中「阶段·目标」牌无对应信息源,均被清除);已有元素可以改形态改位置,不可无中生有;学习参照(BG3 底栏双圆锚等)只当手法库,采纳前必须先过功能对应这一问。
谁拍板:用户(2026-07-10 原话「左右两个大型圆形按钮是干啥用的?大的离谱」「之前的问题就是把我们游戏里面没有的交互和信息也学了」);推翻条件=对应功能真的立项落地后可重新引入该形态。
判例:CMT-2026-07-10-010、CMT-2026-07-10-011、DEC-2026-07-10-006。
验证件:暂缺(候选:布局图评审检查单加"逐元素真实对应"一项)。
投影:walker 仓 layouts-v2 设计图(修订样板);对照稿 v6(mat_d51a5cf5)。
规模与接入:暂缺。

## 布局·成熟游戏HUD铁律

结论:HUD 全部贴屏幕边缘生长,禁悬浮居中卡片;场景 100% 满屏铺底;繁复靠轮廓剪影与端头/中点饰件,不靠框内多线;转角语言分工制(圆=仪式锚且全屏≤3处、斜切=面板、直角=功能格)且各类内部全局统一。
什么时候:
  注入/触发:任何屏级布局设计/改版时;判断类型=规则(对照四条逐验)。
  成立情境:2026-07-10 起;源自 BG3/神界原罪2/LOL/文明6 四款 1920×1080 实测归纳,用户认可"设计稿大体说明"(全宽贴底 vs 保守原尺寸的终裁仍开放,见候选)。
判断怎么下:先量化再判——死空间占比(现状曾左右各 19%)、贴边与否、每面板亮线条数、转角语言种数;评估任何新面板时按四条铁律走查;向参照游戏学习时注意各家分工制细节(BG3 装饰在边框中点而非四角、DOS2 繁复全在端头、LOL 层级靠形状不靠线宽)。
谁拍板:方向=用户认可;全宽贴底指挥台 vs 保守原尺寸的定案待用户在对照稿 v6 终裁;推翻条件=用户对布局方向改口。
判例:DEC-2026-07-10-006、CMT-2026-07-10-011。
验证件:现状量化脚本(measure 思路:坞bbox占比/金线段厚度/线噪行数,walker 轮次日志有实测记录);暂无常驻机检。
投影:布局图 layouts-v2;对照稿 v6;S8 接入后落 battle.css/screens.css。
规模与接入:暂缺(walker 未注册 omni 管线)。

## 图案·线宽相对论

结论:线的粗细相对整屏画面判断,不相对组件;亮金线有最小宽度阈值(当前 3px@1080p),更细的分隔一律改暗色凹槽;每面板只允许一条亮色主线,内部分隔全部走暗凹槽。
什么时候:
  注入/触发:出任何带线框的 UI 资产、写 CSS 边框/分隔、审生成图时;判断类型=规则(量线宽/数亮线)。
  成立情境:2026-07-08 用户"最小线宽"反馈起,2026-07-10 收敛为"亮3px/暗凹槽"两档制。
判断怎么下:金细线在暗底上读作噪音、暗凹槽读作结构——要分隔就用凹槽,要强调才用亮线;数一个面板的亮线条数,超过 1 条主线即超标(现状教训:坞顶框曾是 3 条 1px 亮金线叠成);Art Deco 语汇天然爱细线,生成 prompt 里必须显式写线宽下限。
谁拍板:用户(第二十六轮#4 原话"有些线太细了…要相对画面整体的细");推翻条件=分辨率基准变化时重定阈值。
判例:DEC-2026-07-08-001、DEC-2026-07-10-006、DEC-2026-07-12-007。
验证件:**线重自动门禁已建**(walker tools/ops/ui2/frame_lineweight.py,入 e2e 套件首位):解析全部 border-image 声明,量"源纹理线宽×缩放比"的实际渲染线宽,基准=确认布阵钮件(1.93px),任何框件最细线不得低于基准×0.95;受检件墨掩码 7px 闭运算防斜面阴影沟劈出假细线。抹线处置已被用户否决——过不了门禁的件要**重生成线更厚夹边更厚的版本**,不是把线删掉。
投影:artdeco/hextech canon 风格词;battle.css/screens.css;e2e 套件 frame-lineweight 项。
规模与接入:脚本级(walker npm run test:e2e 首项)。

## 图案·资产禁拉伸

结论:任何时候 UI 素材都不能被拉伸——border-image repeat 一律 round 禁 stretch;平铺纹理必须过 offset-50% 接缝校验;切片预览必须按 CSS 真实行为渲染再目检。
什么时候:
  注入/触发:九宫格切片、border-image 接入、平铺底纹接入时;判断类型=规则+目检。
  成立情境:2026-07-08 用户明令"素材必须在任何时候都不能被拉伸"起,全资产族适用。
判断怎么下:连续几何纹样选 round(整数重复自适应),渐变光泽条这种唯一可 stretch 的例外也要先问"能不能改成 round 兼容的纹样";平铺资产跑 check_tileable(暗角网格与接缝);slice 用百分比与分辨率解耦。
谁拍板:用户明令;无已知推翻条件。
判例:DEC-2026-07-08-002、DEC-2026-07-07-168。
验证件:aigc-lab gen/check_tileable.py(机检+对照图目检);slice_nineslice.py 预览。
投影:全部 v2/hextech-v1 资产接入 CSS;canon 踩坑节。
规模与接入:脚本级快速入口(aigc-lab gen/ 工具族)。

## 图案·容器与数据件分工

结论:容器类资产(框/坞/面板)整件带底全出血生成、CSS border-image 接入、不抠图;数据件(血条/段条/角标/文字)禁贴装饰图,只用 CSS 金调槽化;按钮/小卡容器禁用 border-image 的 fill,内里由元素自带底色+纸纹。
什么时候:
  注入/触发:规划新资产族、写接入 CSS 时。
  成立情境:2026-07-07~08 三轮实证后长期有效。
判断怎么下:容器抠图会带 halo 且金线易断,整件出血由 CSS 开窗;数据件是信息层,贴图会污染可读性(clarity parity);fill 关键字有两坑——语法上必须紧跟 slice 否则整条声明静默失效,视觉上会盖出黑底(第二十六轮#6 用户点名)。
谁拍板:用户反馈+实证;推翻条件=渲染管线更换。
判例:DEC-2026-07-07-168、DEC-2026-07-07-169、DEC-2026-07-08-003、CMT-2026-07-07-007。
验证件:e2e 视觉走查(walker npm test:e2e 五套)。
投影:battle.css/screens.css 全容器声明;canon 规则节。
规模与接入:暂缺。

## 图案·装饰浓度分区

结论:装饰浓度按界面性质分区——仪式性界面(主菜单/结算/奖励/事件幕)拉满,高频操作面(战斗坞/悬浮件/功能槽)做减法;数据件区域内禁装饰叠加。
什么时候:
  注入/触发:给某界面定装饰规格、选锚定图浓度档时。
  成立情境:2026-07-07 立项调研(Prey 式分区)起。
判断怎么下:先问界面停留时长与操作频率——高频面上装饰是税,仪式面上装饰是体验;两档浓度对应两张锚定图(A 标准浓度/B 仪式浓度),生成时选对锚;性能同理:高频面禁整容器 filter 逐帧动画(曾致 p95 133ms)。
谁拍板:用户批准计划;推翻条件=用户要求全域拉满。
判例:DEC-2026-07-07-170、DEC-2026-07-07-166、DEC-2026-07-08-005。
验证件:test:perf:battle 性能门禁(p95>33ms 或单帧>200ms FAIL)。
投影:canon 规则 1(两锚 asset_id);battle.css 动画通道。
规模与接入:脚本级(walker npm run test:perf:battle)。

## 图案·填充密度

结论:界面里空白间隙要少,各元素由内容撑满、紧凑内距;大片空底色即不合格;头像/立绘充满其框位,时间轴的卡片条、背景、标尺都必须 UI 风格化(饰卡造型/底纹/雕刻数字带),不允许裸矩形裸底。
什么时候:
  注入/触发:评审任何界面/概念图、写生成 prompt、设计面板内容排布时;判断类型=目检(找大片底色)。
  成立情境:2026-07-11 用户立此指标起,walker 全界面通用。
判断怎么下:逐面板问"这块底色上有没有内容"——顶栏一长条空底、详情面板半边空底浮个小人都是反例;撑满的手段=内容放大(立绘/头像出血充框)、信息补位(把该有的信息放进来)、纹理垫底(底纹/暗花),而不是加装饰线;详情面板显示立绘而非棋子小人。
谁拍板:用户(2026-07-11 原话"空白部分也就是间隙应该较少…大片的底色很不好看");推翻条件=用户对某界面点名要留白。
判例:DEC-2026-07-11-006。
验证件:暂缺(候选:截图底色连通域面积占比量测)。
投影:tasks v5 起的生成 prompt(density 硬指标段);后续 CSS 接入。
规模与接入:暂缺。

## 生成·风格锚定与多版本

结论:一切 UI 资产批次第一参考=风格锚定图(asset_id 入 canon);同族部件一张 sheet 同批生成再切;每任务 n=3~6 多版本全保留不删;入仓前逐张放大检查;跨轮反漂移靠**认可锚点总表**——各方面取用户第一次明确认可的版本为形态权威,新批次只携带用户点名的差量,两锚冲突取更晚的用户指令。
什么时候:
  注入/触发:任何 AIGC UI 资产批次开工时;多轮迭代出现"改着改着走样"迹象时查锚点总表。
  成立情境:2026-07-07 起(方法论沿自立绘产线规则 1/9);认可锚点总表 2026-07-11 立(DEC-2026-07-11-043)。
判断怎么下:纯 prompt+seed 一致性只有四到六成,锚定图参考可到八九成;跨批次一致性=锚定图+逐字风格词双保险;锚升级=独立新版本不覆盖;落选候选保留可复裁(黑金锚定案时墨绿金/酒红金全量留档);每个"方面"(布局骨架/now线/填充密度/悬浮件/相位icon…)单独记锚,验收时对表逐项走查而不是凭整体印象。
谁拍板:方法论用户批准;锚定图与各方面锚点由用户明确认可才登记;推翻条件=生成模型换代重验一致性/用户新指令换锚。
判例:DEC-2026-07-07-166、DEC-2026-07-07-165、DEC-2026-07-11-043。
验证件:canon 台账(批次/run id/asset_id 可回溯);认可锚点总表(walker 计划文档 10.8 节)。
投影:aigc-lab gen/tasks-walker-ui-*.json 版本族;runs/ 全保留。
规模与接入:脚本级(aigc-lab gen/batch.mjs)。

## 生成·设定权威链与误读处置

结论:角色/世界观设定的权威链=用户口述(最新重申优先)>原始设定图(非 AI 原件)>一切派生件;AI 高清化件只当生产参考,裁定一律回原件;生产纪律=树状探索——不在生成图上迭代生成图,不满意回上一个权威节点另开分支,生成图之间绝不串成链;原画兼为画风基准,风格漂移=报废回根重出。
什么时候:
  注入/触发:出任何角色相关资产、写身份 prompt、判定产物是否合格时;用户重申某设定("我再说一遍")时立即触发全链核查。
  成立情境:2026-07-14 三次实证(S17 画风漂移/S18 参考糊/巨型十字架误读)后定案。
判断怎么下:身份要素与画风逐项从权威件取,禁凭生成结果反推设定;**语义不明的用户反问(如"你知道 X 是怎么回事吗")禁自行反向解读**——当场追问或按用户字面主张执行(判例:该反问被错解为"X 是漂移应删",实际 X 正是设定本体,错误进了 canon 波及全部相关资产);用户重申=误读红色警报,处置=改权威锚点+作废错误判定+清点全部波及资产排队重出;高清化件入库要逐项对照原件验身份后才可当参考。
谁拍板:用户(设定唯一权威);推翻条件=用户改设定。
判例:DEC-2026-07-14-018、DEC-2026-07-14-022、DEC-2026-07-14-025。
验证件:walker canon 11.5/11.5b/11.6/11.6b(权威路径与树状探索条款);hd 参考件台账(walker-hd-ref-map.json)。
投影:curated/character-originals(+hd/);S23 全批重出;群青小人纠正队列。
规模与接入:脚本级(aigc-lab gen/batch.mjs)。

## 生成·朝向与姿势参考纪律

结论:小人朝向判据=脸/视线/躯干开合方向,**绝不以兵器指向判**(武器拖尾是蓄势姿势的一部分);姿势参考只借姿势(prompt 显式声明并忽略其形象/服装/兵器),参考件逐件人眼核对朝向并记档,确认朝左才镜像;产物逐张查两件事:朝向(同判据)+身份污染(参考件细节渗入=报废该张)。
什么时候:
  注入/触发:出小人/立绘/攻击帧、挑姿势参考件、镜像操作前、产物 QA 时。
  成立情境:2026-07-14 同一朝向错误二次犯(S18"摆的朝左才朝左"+S24"原件本就朝右被我镜像翻反")后立死。
判断怎么下:摆什么朝向就出什么朝向——参考件的朝向错误会原样传导且文字纠不回来;"剑尖指左"可能是"蓄势向右挥"的朝右站姿,人眼读脸与躯干才可靠;镜像是高危操作,必须建立在核对结论之上而不是印象之上;身份污染实证=马甲/骷髅护手曾从参考件渗进产物,故 POSE REFERENCE ONLY 声明+逐张检查两道都不能省。
谁拍板:用户(两次纠错原话);推翻条件=无。
判例:DEC-2026-07-14-020、DEC-2026-07-14-024、DEC-2026-07-14-031。
验证件:walker canon 12b/12d(判据与流程);选稿材料逐张标注(净/污/朝向)。
投影:S24 动作页定稿(C2);scratchpad limbus-refs 核对记录。
规模与接入:脚本级。

## 生成·同页连续生产与尺寸基准

结论:同一角色的一系列动作(常态/攻击)必须在**一张图里同幅同基线**生成再切片——分图生成头身比必互漂;入库过归一化基准:画布高统一、人身高定标(四头身→头等大)、脚底线统一,浮游武器/持杖角色量人身时列窗排除武器,**攻击帧不独立定标、沿用同角色常态格的比例因子**;渲染端固定系数,因为上板实际大小=世界高度×人物在画布中的占比。
什么时候:
  注入/触发:出小人动作页、切片入库、发现板上单位大小不齐时。

## 图案·卡图分镜简报法

## 生成·prompt有效性与参考件分工

结论:纯文字 prompt 压不住四类漂移,各有对应治法——①透视错乱:机位/姿势/透视缩短一致性条款进 prompt+产物逐张 QA ②渲染档跑偏(如矢量档出厚涂):给**风格参考件**(已入库合格件,声明 only for rendering style) ③低档位出精致五官:病根是挂了人设肖像参考,肖像会把精致渲染腔整体带进去——低档位一律撤肖像,身份靠发色/剪影文字锁定 ④武器/设定漂移:描述从 canon 锚点逐字取,禁即兴改写。参考件的"渗透"是双刃:身份参考会渗风格(③),风格参考会渗内容(需声明 do NOT copy subject),**每个参考件用途必须显式声明且单一**。
什么时候:
  注入/触发:设计任何生成批次的 prompt 与参考件组合时;产物出现风格/透视/设定漂移时定位病根。
  成立情境:2026-07-14 S22 整批四病点评+S23 重出验证(21 张 20 过)后。
判断怎么下:漂移先归因到"文字压不住"还是"参考件带偏"——前者补条款/换参考件,后者调整参考件组合;风格参考件选自己库里已合格的产物(同宇宙同调色,零内容语义冲突);QA 实拦判例:痛楚感知首版形象漂移(盘发/耳坠/美甲)当场报废按身份锁定条款重出,证明条款不是纸面。
谁拍板:用户点评定病,治法实证定案;推翻条件=生成模型能力变化。
判例:DEC-2026-07-14-026、DEC-2026-07-14-023、DEC-2026-07-14-024。
验证件:walker docs/specs/card-art-storyboard.md 三·七节(四条硬化全文);S23/S23b 批次实证。
投影:风格参考件上传台账(灼烧/猛火点燃徽记 asset_id);S23 任务 prompt 结构。
规模与接入:脚本级(aigc-lab gen/batch.mjs)。

## 生成·构图参考与模型主导

结论:整屏概念图生成以"素颜真实截图(管内容)+风格样张(管材质)"为参考基座;手绘设计图**只传布局骨架级功能约束**(写进 prompt:贴边/无虚构元素/关键件位置/主体区占比不得缩水),**装饰造型层交图形模型主导**——AI 手绘线框细化到造型反而拖低质量;每轮并行出模型主导版对照。
什么时候:
  注入/触发:出整屏/整面板效果图、给设计改版出概念稿时。
  成立情境:2026-07-10 两次纠偏+2026-07-11 第三次纠偏(线框干扰实证)后确立。
