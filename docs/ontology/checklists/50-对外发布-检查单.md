# 50-对外发布 · 检查单

扫描单(防漏看),不承诺照做全对——判断细节以手册条目正文为准,临场拿不准就回读原条目。

## 逐条过 · 之1

- [ ] **工作规范与连续性信息分层** — 发布 Agent 的工作规范统一进入操作手册；Memory 只保存身份连续性、真实发布状态、已公开内容概要和待续主题。(细则见 工作规范与连续性信息分层)
- [ ] **写作前读取已公开内容概要** — 写作 Agent 动笔前必须读取真实发布状态和逐帖概要，确认本篇新增信息并删除对前帖的无意义重复。(细则见 写作前读取已公开内容概要)
- [ ] **完整事实母稿先于载体适配** — 先写一份不受平台字数、图片张数和时长限制的完整事实母稿，再决定图文、长文、视频或分篇。(细则见 完整事实母稿先于载体适配)
- [ ] **当前产出优先于形成过程** — 涉及项目或管线的文章，先让读者知道这段时间具体做成了什么、现在能解决什么，再讲形成过程和纠错。(细则见 当前产出优先于形成过程)
- [ ] **事实展开到陌生读者可复述** — 每个关键案例必须写清对象、当时在做什么、采取了什么动作、出现了什么问题、怎样修正、得到什么结果和还剩什么边界。(细则见 事实展开到陌生读者可复述)
- [ ] **数字必须带对象与口径** — 数字首次出现时必须同时说明它统计什么、统计范围、相关动作、结果含义和已知限制。(细则见 数字必须带对象与口径)
- [ ] **用户动机必须有明确来源** — 只有 ColorC 明确说过的目的、感受和取舍才能归给 ColorC；可观察事实与编辑判断必须使用各自的表述。(细则见 用户动机必须有明确来源)
- [ ] **经验分享文体** — 经验分享同时交代做了什么和从具体纠偏中得到什么；它保留选择过的事实链，避开逐日流水和规格书式全量罗列。(细则见 经验分享文体)
- [ ] **单篇中心与容量分流** — 每篇只解决一个中心问题；正常字号和自然叙述达到容量上限时，优先换载体或分篇。(细则见 单篇中心与容量分流)

## 逐条过 · 之2

- [ ] **图卡承担结构化信息且保持可读字号** — 图卡用于承载结构、对照、流程、界面证据和重点案例；正文负责连贯叙述，任何关键内容不得靠过小字号塞入。(细则见 图卡承担结构化信息且保持可读字号)
- [ ] **视觉主题的意义不得代拟** — DOS终端主题的含义按ColorC明确表达记录：它包含对语言模型重新回到bash式操作环境的感慨；跨页面视觉一致性是独立目标，二者不得拼成未经确认的单一动机。(细则见 视觉主题的意义不得代拟)
- [ ] **公开叙述、内部来源与平台 AI 标识分层** — 公开正文用ColorC视角，不出现Agent/Model tag；完整来源进内部证据；每篇在小红书高级选项开启并复验AI内容标识。(细则见 公开叙述、内部来源与平台 AI 标识分层)
- [ ] **发布传输默认关闭并禁止规避平台控制** — 浏览器和ADB发送默认关闭；只允许正常平台界面、真人确认、AI标识复验和回执。禁止指纹伪装、验证码绕过、风控规避、隐藏自动化或关闭AI标识。(细则见 发布传输默认关闭并禁止规避平台控制)
- [ ] **写作阶段自检先于独立审查** — 写作Agent先按同一操作手册完成自检，独立审查员只负责寻找遗漏和提供证据，不能成为质量的主要来源。(细则见 写作阶段自检先于独立审查)
