# Bilibili 视频与有格式长文操作手册

适用范围：Bilibili 网页端视频投稿与专栏文章。Qwen 负责全部对外中文，确定性工具只负责文件核验、格式转换、图片渲染、浏览器装配和读回检查。视频最终公开发布与专栏最终公开发布都保留给 ColorC 本人。

## 载体决策

- Bilibili 专栏是长文载体，不继承小红书的纯文本、3:4 图卡、正文长度、图卡数量和预设拆篇限制。
- 写作前不设置目标字数上限。文章应先自然写完整；只有真实平台上限、读者结构或主题变化要求时才拆篇。
- 当前网页编辑器实测正文上限为 100000 字，标题提示为 30 字以内。打包器只硬拦正文真实上限；标题超过 30 字产生警告，不自动改写。
- Markdown 是文章真源。发布包只由真源确定性生成，禁止在灌入编辑器时临时补写、压缩或改写公开文字。

## 封面

- 每篇专栏必须准备自定义封面，不使用平台自动抓取正文开头文字的默认封面。
- 封面可见中文由同一个 Qwen 成文会话写入独立 Markdown 文字源；视觉实现者只负责素材、HTML/CSS、裁切和渲染。
- 封面先按手机端专栏卡片的小缩略图设计，再输出 1920×1080 PNG；不得反过来只在原图大画布上检查美观。
- 每次渲染同时生成 178×100 和 320×180 诊断缩略图。178×100 中主标题必须可辨认；看不清的副标题、小字、界面截图和细线装饰都按噪声删除。
- 真实截图只在缩小后仍能形成粗粒度、可辨认的主视觉时放入封面。详细界面证据放在正文相关段落，不为了“封面有真图”强塞进缩略图。
- 标题与粗粒度视觉锚点位于中央安全区。上传后还要检查 Bilibili 实际裁切预览；裁切不完整时只调整布局，不改写 Qwen 文字。

## Markdown 映射

直接转换为 Bilibili 富文本：

- 段落与换行；
- 标题；
- 粗体、斜体、删除线和行内代码；
- 链接；
- 有序列表、无序列表；
- 引用与分隔线。

保持在原文位置插入图片：

- Markdown 图片；
- 代码块；
- 表格；
- 任务列表、包含图片的复杂列表；
- 原始 HTML 和编辑器不能稳定保持的其他块级结构。

代码块、表格等由本地 HTML/CSS 渲染为 PNG。可见文字逐字来自 Markdown 真源，渲染器不能添加新标题、说明或图注。远程图片必须先本地化并通过公开安全检查，未本地化时发布包不得进入浏览器运输。

## 默认运输层

默认使用 ColorC 自己的日常 Chrome、当前本人账号和 Bilibili 原生专栏编辑器：

1. 人工保持 Chrome 与账号正常登录。
2. 助理在真实标签页的空编辑器中，一次粘贴打包器生成的自包含富文本片段；本地图片已经内嵌在片段中，由 Bilibili 编辑器原生转换为正文图片节点。
3. 默认禁止把文章拆成多段反复粘贴。Bilibili 上传图片时会短暂增删占位节点，分段操作容易让选区回到旧段落。禁止用 `Ctrl+End`、屏幕坐标或视觉猜测正文末尾。
4. 一次粘贴后读取编辑器结构；定位或图片数量不符就停止，禁止原样高速重试。
5. 打开“自定义封面”，上传本篇封面并检查平台裁切结果。
6. Agent 文章必须在正文第一行保留完整 `[Agent：… Model：…]` tag，并勾选平台“AI 辅助创作声明”。
7. 只保存草稿；最终发布由 ColorC 人工执行。

禁止导出 Cookie、复用未公开接口、抓包重放、指纹伪造、验证码处理和风险提示规避。Patchright 只保留为诊断参照，不是默认运输层。

## 最小两步流程

### 一、Qwen 写 Markdown

输入只包含目的、平台手册、中立材料目录和需要延续的已发布原文。Qwen 直接写 `title.txt` 与 `article.md`；Agent 成文时 tag 位于 `article.md` 第一行。

### 二、确定性打包与浏览器草稿

```powershell
python -m omnicompany.packages.domains.bilibili_publish.markdown_package `
  --title-file <title.txt> `
  --markdown-file <article.md> `
  --output-dir <output-dir> `
  --authorship agent
```

默认拒绝覆盖非空目录。只有目标目录已含本工具生成且 `channel=bilibili_article` 的 manifest 时，才允许显式添加 `--overwrite` 重建，避免误删其他材料。

打包器生成：

- `manifest.json`：按顺序列出的富文本和图片片段；
- `browser-assembly.json`：一次性富文本装填与最终读回合同；
- `article-fragment.html`：直接粘贴到空编辑器的自包含富文本片段，图片以内嵌数据承载；
- `segments/*.html`：用于诊断和核对的分段副本，不作为默认运输输入；
- `assets/*.png`：编辑器不稳定支持的 Markdown 结构；
- `article-preview.html`：本地连续文档预览；
- `title.txt`：标题的确定性副本。

浏览器装配完成后必须读回：标题、正文第一行 tag、标题数量、图片数量、关键段落、AI 声明勾选状态和“保存成功”。任一项不一致就停在草稿，不进入发布。

已验证 Bilibili 接受一次粘贴包含多张内嵌 PNG 的富文本，并按原文位置生成正文 `figure/img` 与图片注释节点。分段粘贴会受到图片上传占位节点和旧选区影响，因此不再作为默认运输方式。

### 浏览器草稿自动化入口

浏览器运输不再拆成由当前助理逐步临时执行的点击命令。固定入口为：

`src/omnicompany/packages/domains/bilibili_publish/browser_draft_automation.mjs`

每篇任务在任务根目录保存一份 `browser-draft-task.json`，登记打包目录、自定义封面、目标草稿地址、`new` / `existing` 模式、可选的 `replace_existing_body` 正文替换开关、`ensure` / `replace` 封面模式、`full` / `settings` 读回范围和读回文件。只修改封面或声明时使用 `settings`，避免用本次没有改写的旧正文结构阻断设置读回；新稿装配和既有正文替换必须使用 `full`。调用 `runBilibiliDraftTaskFile(...)` 时只传入已经连接的本人 Chrome 与任务文件；入口在一次任务中完成：

1. 校验 `manifest.json`、`browser-assembly.json`、标题、富文本片段和封面均存在，并确认终点是 `stop_before_publish`。
2. 新草稿只接受空编辑器，一次粘贴完整富文本；已有草稿必须等待标题与非空正文同时加载完成，才允许补齐设置和读回。等待期间禁止保存。只有任务文件显式设置 `replace_existing_body: true` 时，才允许在原生编辑器内全选清空并一次性粘贴新富文本，随后执行完整读回。
3. 等待 Bilibili 原生编辑器完成正文图片转换，核对标题层级和图片数量。
4. 勾选 AI 辅助创作声明，上传并确认自定义封面。
5. 保存草稿，读回标题、首行 tag、正文字符数、标题数、正文图片数、AI 声明、编辑器封面和保存成功状态。
6. 打开“图文管理 → 草稿 → 专栏”，按标题定位刚保存的草稿卡片，等待封面图片的真实宽高大于零后再读回。只看到 `<img>` 节点不等于封面已加载；编辑器内的封面节点与草稿列表封面必须同时通过。
7. 将两处读回结果写入任务目录；入口没有发布动作，也不查询或调用 Bilibili 私有接口。

Chrome 扩展或其他浏览器连接器只承担“连接本人现有浏览器登录态”的运输职责。页面操作顺序、选择器、前置条件、等待和核验均由上述入口负责，后续任务不得再逐步骤临时拼装。

### 单标签页原则

- 优先接管当前已经打开的 Bilibili 标签页；同一篇任务从编辑、保存到草稿列表回读始终复用这一标签页。
- 保存完成后直接在原标签页进入“图文管理 → 草稿”验证封面，不为回读另开标签页或窗口。
- 只有当前会话没有可用标签页时允许创建一次；创建后整项任务继续复用它。
- 禁止为重试、重新连接或重复核验连续创建新窗口。发生连接中断时先重新接管原标签页；确认原标签页不存在后才创建替代页。

## 视频投稿运输层

视频投稿与专栏共用“本人日常 Chrome、本人账号、原生创作中心、草稿终止、人工发布”的边界，但输入合同不同。视频不经过 Markdown 打包器；每期在 `episodes/<episode>/release/<target>/` 保存一套可复核发布包：

- `publication.json`：Qwen 文案策划 Agent 在完整视频上下文中独立产出的标题、简介、标签、分区候选、AI 声明、封面文字和章节；
- `browser-task.json`：只含运输事实与安全策略，包括成片、封面、最终 QA、读回回执的路径和已确认哈希；
- `cover.png`：1920×1080 封面，另附 178×100 诊断缩略图；
- `draft-readback.json`：账号侧草稿保存成功后写入的本地回执；公开发布前不存在是正常状态。

固定入口为：

`src/omnicompany/packages/domains/bilibili_publish/video_draft_automation.mjs`

本地预检：

```powershell
node src/omnicompany/packages/domains/bilibili_publish/video_draft_automation.mjs `
  --check <browser-task.json>
```

预检必须同时确认：

1. `publication.json` 与 `browser-task.json` 都保留 `human_only` 发布边界；
2. 成片字节数和 SHA-256 与任务合同一致，最终 QA 明确记录同一哈希和通过结果；
3. 封面是 1920×1080 PNG，哈希与任务合同一致；
4. 标题、简介、标签、章节、分区候选和 AI 辅助声明字段齐全；
5. 任务遇到重复稿、验证码、登录失效、账号风险或未知页面结构时一律停止。

浏览器运输按以下状态推进：

1. `PREPARED`：本地预检通过；
2. `UPLOAD_BOUND`：复用当前已登录的 Bilibili 视频投稿标签页，定位唯一的视频文件输入；
3. `VIDEO_UPLOADING`：只选择一次已核哈希的成片，等待平台显示文件名、上传进度或投稿表单；定位失败后重新读取页面，不原样高频重试；
4. `METADATA_FILLED`：按 Qwen 发布包填写标题、简介、标签，按页面真实选项选择最接近的分区和原创声明；
5. `AI_MARKED`：勾选页面当时提供的 AI 辅助内容声明并读回；
6. `COVER_ATTACHED`：上传已核哈希封面，检查平台实际裁切预览；
7. `DRAFT_SAVED`：点击保存草稿，从编辑页和视频草稿管理页读回标题、视频文件、封面、分区、标签、AI 声明和保存状态；
8. `USER_REVIEW_REQUIRED`：停止自动操作，由 ColorC 检查并决定是否公开发布。

Chrome 扩展承载本地文件上传时，必须在扩展详情中启用“允许访问文件网址”。若文件选择器没有打开，运输立即停止并提示开启权限；不得改走 Cookie 导出、私有上传接口或把 38 MB 级成片编码进页面脚本来绕过权限。

视频标题、简介、标签和封面可见文字不得由浏览器自动化临时补写。主 Agent 可以做事实、结构和零背景可理解性审阅；需要改文案时必须回到同一个 Qwen 文案策划会话独立修订，再重新生成封面和任务哈希。

## 检查单

- [ ] 标题与正文均来自 Qwen 文字源或明确的人类原稿。
- [ ] 没有事先字数压缩、图卡数量限制或小红书格式残留。
- [ ] Agent 成文的完整 tag 位于第一行，模型名称精确。
- [ ] Markdown 图片均已本地化并通过隐私与公开安全检查。
- [ ] 代码块、表格和其他不稳定格式已经渲染成图片。
- [ ] manifest 中不存在 `render_required=true` 或远程图片警告。
- [ ] 浏览器使用本人日常 Chrome 与原生编辑器，没有私有接口调用。
- [ ] 编辑器读回的富文本层级、图片顺序和正文关键段落与 manifest 一致。
- [ ] 正文从空编辑器一次粘贴完成，没有使用逐段重放、`Ctrl+End` 或屏幕坐标猜位置。
- [ ] 自定义封面已经上传；封面文字来自 Qwen 文字源，178×100 诊断图中主标题可辨认，平台裁切预览中标题和关键视觉完整可见。
- [ ] 保存后已经在“图文管理 → 草稿 → 专栏”按标题找到对应卡片，且卡片封面缩略图加载成功。
- [ ] “AI 辅助创作声明”已经勾选并读回。
- [ ] 草稿保存成功；发布按钮由 ColorC 人工点击。
