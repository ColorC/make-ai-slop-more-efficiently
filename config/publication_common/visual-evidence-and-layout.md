# 对外发布共用视觉证据与版式准则

适用范围：个人网站内容生产、小红书图文、后续接入的其他公开发布载体。各渠道可以保留自己的尺寸、视觉主题和交互形式，但素材取舍与信息编排统一遵守本文。

所有公开可见中文的作者边界先遵守 `production-copy-authorship.md`：标题、标签、批注、图注、封面字和阅读扩展文字均由本次选定的成文作者独立写入文字源；Codex、Claude 和确定性渲染工具只负责素材、结构、布局、样式与逐字装配。

## 一、素材优先级

公开内容先寻找能够直接证明“做了什么”的真实画面，顺序如下：

1. 已公开网页或真实产品界面的截图、录屏。
2. 真实运行结果、图表、作品图、日志输出和可公开文档片段。
3. 从上述材料裁切出的局部，并配必要的圈画、箭头和短注释。
4. HTML/CSS、表格、流程图形成的结构化解释图。
5. 纯文字卡。仅在前四类都无法准确承载该信息时采用。

当真实画面可以公开并能说明问题时，优先使用它，不能只把同一信息重新写成文字。真实网页产品在个人网站上优先提供可交互 demo；迁移到小红书等静态载体时，优先放该 demo 或网页的真实截图。

真实画面还必须直接证明当前图卡的主题。为了满足“至少一张真图”而挪用无关网站、数据页或旧审阅页，会制造错误暗示；没有对应真图时使用诚实的 HTML/CSS 结构图，不能拿无关截图占位。

## 二、发布安全检查

截图进入公开产物前逐张确认：

- 页面本身已经公开，或画面内容已获公开授权。
- 不含公司业务、内部项目名、真实姓名、账号、IP、密钥、内网地址、本地路径、未公开仓库或其他敏感信息。
- 裁切与圈画没有改变原图结论；不得拼接出原页面不存在的状态。
- 必要时只裁掉无关边缘、遮盖敏感局部，并在文案中说明画面的真实来源与时间边界。
- 有真实界面时不得用生成模型仿造界面。生成模型仅可补充非事实性的局部素材或更自然的圈画。

## 三、统一主题不等于统一模板

颜色、字体、线条、终端提示符、页码和标识可以形成统一视觉身份。每张图仍要根据自己的信息任务选择结构。先做分镜，再选择版式；禁止把全部内容套进同一组“眉题＋标题＋正文＋三条列表”。

常用版式包括：

- 封面：一句中心问题或结论，加一处视觉锚点。
- 截图主视觉：真实画面占主要面积，文字只负责指出观看重点。
- 圈画截图：对真实画面做局部放大、编号、箭头或批注。
- 流程：按时间或阶段展示动作与交接关系。
- 前后对照：同一对象的错误版本、修正动作和当前状态。
- 案例档案：对象、问题、证据、处理、结果分区呈现。
- 数据页：用一个主数字或一张真实图表承载结论，补充口径与边界。
- 引文页：保留需要被讨论的原句，再给出撤回或修正说明。
- 收束页：当前能力、未接通部分、下一步或读者入口。

同一组连续图卡中：

- 相同主版式不得连续出现超过两张。
- 任一主版式不得占整组图卡的 40% 以上。
- 至少包含三种主版式；五张以上的图组至少包含一张真实截图或真实产物图。
- 每张图只承担一个信息任务。版式变化服务信息，不为装饰而变化。

## 四、图片的两种内容模式

分镜时每张图必须明确选择一种模式，不能在渲染后再用“放不下”解释压缩语法：

### 演示图

- 以截图、示意关系、流程、对照、数据或圈画为主，遵守“少字多图”。
- 整组图按 PPT 式演示组织。读者只看图片，也能复述对象、发生了什么、关键关系和当前结论。
- 文字只承担标题、标签、图注和必要解释，不复制正文段落。

### 阅读扩展

- 图片被明确当作文章的额外阅读页，可以容纳比普通演示图更多的完整文字。
- 文字必须使用自然句子并保持可读字号；不能省略主语、背景、因果或专名解释来换取篇幅。
- 阅读扩展补充正文没有展开的材料，不把正文重新说一遍后得到更模糊的版本。

同一张图不得混用两种模式。容量不足时增加图卡、拆成系列帖或改用长文；不能缩字、堆短语或删除语法成分。

图文完成后执行冗余检查：逐张写出“这张图比正文新增了什么”。答不出来的图应删除或重做。文字换行还要按语义组检查，避免把“开源与读者选题”一类短语拆成难看的孤行。

## 五、渠道落地

### 个人网站

- 有真实网页界面的项目直接提供真实界面 demo；截图作为列表预览和静态补充。
- 长文中的核心机制优先使用真实图、表格、流程图、时序图或输出样例。
- 任何视觉材料都必须能回到项目真源。

### 小红书

- 完整图卡由 HTML/CSS 排版后按 1080×1440 渲染；真实截图作为其中的内容层。
- DOS 终端风格是一套视觉主题，不能成为十张相同窗口模板。
- 关键正文不低于 42px，标题通常不低于 64px；截图中的原生小字不承担主要解释，必须另配可读批注。
- Reviewstage 只承担审阅，保持中性工具界面。

### Bilibili 专栏

- 每篇专栏都准备自定义封面，不使用平台从正文开头自动抓取文字的默认封面。封面字逐字来自成文作者的文字源，视觉实现者只处理真实素材、结构、HTML/CSS、裁切与渲染。
- 封面先按 178×100 的手机端专栏卡片缩略图设计，再渲染 1920×1080 原图。缩略图中主标题必须可辨认；无法辨认的副标题、小字、细节截图和细线装饰都视为噪声。
- 真实画面只在缩小后仍是一个粗粒度、可辨认的主视觉时用于封面。更细的界面证据应放在正文相关段落，不得为了形式上“有真图”破坏封面的缩略图可读性。
- Markdown 长文是内容真源，允许标题、段落、列表、引用、链接、文中图片和连续长篇结构，不继承小红书的纯文本、3:4 图卡、图卡数量或预设正文长度限制。
- 真实截图、运行结果、图表和作品图直接放入相关段落附近。图片顺序属于文章结构，不能统一挪到开头或结尾。
- Bilibili 编辑器能够稳定承载的 Markdown 结构转换为原生富文本；代码块、表格、任务列表和其他不稳定结构由确定性 HTML/CSS 渲染成图片，放回原始 Markdown 位置。
- 这些格式图片只呈现 Markdown 已有内容。渲染器不得新增标题、图注、解释或结论；需要新增公开文字时退回成文作者的文字源。
- 长文先自然写完整，再由主题与阅读结构决定是否拆篇。正文只受平台真实上限约束，不为适配其他渠道预先压缩。
- 默认运输层是本人日常 Chrome 与 Bilibili 原生专栏编辑器；自动化只负责富文本粘贴、原生图片插入、AI 标识、草稿保存和读回，最终发布由人执行。

## 六、交付检查

- [ ] 已列出可公开的真实截图、录屏、图表和产物图。
- [ ] 能用真实画面说明的信息没有退回纯文字卡。
- [ ] 每张真实画面都通过发布安全检查。
- [ ] 每张真实画面都直接对应当前图卡的对象与判断，没有无关截图占位。
- [ ] 分镜表为每张图标明信息任务、素材来源和主版式。
- [ ] 每张图已标明“演示图”或“阅读扩展”，且没有混用两种内容模式。
- [ ] 演示图组在脱离正文后仍能讲清主线；阅读扩展使用完整自然语言并提供正文增量。
- [ ] 每张图都能说明相对正文新增的信息，没有更含糊地重复正文。
- [ ] 相同主版式没有连续超过两张，也没有超过整组的 40%。
- [ ] 五张以上图组至少有一张真实截图或真实产物图。
- [ ] Bilibili 专栏已准备并上传自定义封面，178×100 诊断图中主标题可辨认，且平台裁切预览中标题与粗粒度主视觉完整可见。
- [ ] 生成模型没有制作完整信息图或仿造真实产品界面。
- [ ] 全部可见中文逐字来自本次成文作者的文字源；视觉实现者没有新增、删减或改写标签、标题、批注与图注。
- [ ] 最终尺寸、字号、裁切、溢出、文字相撞、语义断行和手机可读性均已检查。
