# 成稿操作单

- [ ] 标题、正文和全部图卡可见文字均由同一个选定作者会话独立写出。
- [ ] Codex、Claude 和核验员没有提供替换句或直接修改公开中文。
- [ ] 语义返修只给原作者会话提供问题位置、用户原话和一手证据路径/切片。

- [ ] 开头先说明当前做成了什么、能解决什么、读者能看到什么。
- [ ] 技术介绍长文先定义对象、读者和边界，再展开当前组件、运行场景、效果证据与限制；正文没有混入形成过程。
- [ ] 路线图文先给当前结论，只选择少数关键转变；每个节点都能回到统一缓存中的事件 ID 与证据。
- [ ] 每个关键案例都写清对象、背景、动作、问题、修正、结果和边界。
- [ ] 原始证据显示内容根本不存在时，已直接使用“编造、虚构、根本不存在”等准确判断，没有弱化成“与材料不符、写得像报告、表述不够准确”。
- [ ] 每篇都写清最终采用的具体设计、实现步骤和当前边界，没有只写“后来调整、加强核对、换了做法”。
- [ ] “删除某段故事”“撤回某个版本”等例子已说明被删内容、证据冲突和处理结果，没有留下只有内部参与者能懂的压缩代称。
- [ ] 每个数字都写清统计对象、范围、口径、含义和限制。
- [ ] 每个陌生概念均已完成处置：优先换成普通称呼；保留专名时就近用一句话解释；适合另文展开时写成“X 是……，之后会单独介绍”。
- [ ] “阻断项”“真源”“轨道”等内部工作词未因检查器要求被强行写进公开正文；普通读者只看到理解当前内容所需的名称。
- [ ] 所有 ColorC 动机与感受都有明确原话来源。
- [ ] 用户的质疑句、反问和审稿问题已经判定语用：若它是在替普通读者指出理解门槛，正文只写可观察的理解障碍，不得写成 ColorC 不知道、困惑或向 Agent 求解释。
- [ ] 正文没有用“ColorC 问/说/反应是”串联多条审稿原话；需要展示坏句与用户原话时，已移入有来源的证据图，正文只保留结论和图前导语。
- [ ] “欢迎评论”没有被扩写成会回复、会采用、会实现或固定选题栏目；每一级承诺都有 ColorC 原话授权。
- [ ] 当前批次的帖子分工没有被写成账号今后的固定内容分类或栏目承诺。
- [ ] Agent 的结构选择和载体选择保持为编辑判断，没有倒推成 ColorC 的动机。
- [ ] 文章同时包含具体工作与可带走的经验，没有退化为逐项流水或设计规格罗列。
- [ ] 前帖已经完整讲过的内容已删除；必要上下文控制在一句到一小段。
- [ ] 禁用句式、空泛口号、孤立结论、重复免责声明和内部生产信息均已清理。
- [ ] 公开文章第一人称始终指发布 Agent；ColorC 的经历、行动、成果、目的、感受和承诺保持第三人称且有来源。
- [ ] 每篇 AI 成文的公开正文首行只有一个 Agent/Model tag，名字与完整模型 ID 准确；协作模型和审查模型仅进入内部运行证据。
- [ ] AI 总结若以“报告摘录”出现，使用引号并忠实对应来源；没有用引号把生成来源包装成人类原话。
- [ ] 正文、标题和全部图卡已合并为一次返修批次；没有按段落或单卡串行调用高级模型。
- [ ] 写作员已读取 `title-patterns.md`，先给出 8 至 12 个克制、具体的标题候选；最终标题能准确预告正文价值，读起来像普通人的实践记录，没有“方案、体系、架构说明、X 与 N 个案例”等内部文档感。
- [ ] 标题没有用“这篇帖子、这样写出来、可算发出来、终于做出来”等空泛指代或发布情绪代替具体对象和动作；没有为了点击添加正文无法证明的数字、结果或冲突。
- [ ] 职业或身份只有在构成本文核心冲突、经验或可信度时进入标题；普通背景信息放在正文。
- [ ] 标题与开头优先交付具体对象、动作、结果或问题，避免“大家好、本人是、今天分享、项目介绍”等公文式入口。
- [ ] 标题与封面只承诺一个可由正文和画面证明的事件；换行按语义组设计，封面不拆出孤零零的助词、宾语或修饰语。
- [ ] 标题、正文和图卡可见文字均不含个人网站网址或域名；需要交代对象时只写“ColorC（账号所有者）的个人网站”等普通称呼。
- [ ] 本篇确实存在值得记录的掉头、错误机制或解决设计；“改了几个版本”“同一内容换载体”等普通迭代不得冒充踩坑。
- [ ] 纯文本正文使用短标题、空行、编号或项目符号形成可扫描层级，同时不依赖 Markdown、HTML 或富文本渲染。
- [ ] 若本文中心是验证公开方法，正文从开头就提出同一个验证问题；每项依次写明“谁提出什么做法 → 本次实际怎样实现 → 观察到什么 → 能下多强的结论”，没有把方法清单拼到另一条叙事后半段。
- [ ] 成稿语言保持完整自然，没有为了预设篇幅省略主语、背景、因果、转折或术语解释。
