# 载体与视觉操作单

- [ ] 全部图卡标题、标签、批注、图注、封面字和阅读扩展文字来自成文作者的文字源文件。
- [ ] 视觉实现者只处理截图、裁切、圈画、结构、版式、HTML/CSS 与渲染，没有新增、删减或改写任何可见中文。
- [ ] 版面需要新增标签或缩短文字时，已退回原作者会话修改文字源，再重新装配。

- [ ] 已在成文作者完成自然成稿后比较图文、长文、视频和系列帖。
- [ ] 载体方案写明每种候选的适配点、容量风险和被否理由。
- [ ] 一篇内容只承担一个中心问题；多个问题已经拆分。
- [ ] 每张图卡只承担一个信息任务，删除后会明确损失信息。
- [ ] 每张图卡已经标记为“演示图”或“阅读扩展”，同一张图没有混用两种模式。
- [ ] 每张图卡同时标明一个明确的信息任务和一个可核对的素材来源；封面也需要真实错误/结果画面作为视觉锚点，不能只有大字。
- [ ] 演示图遵守少字多图，整组脱离正文后仍能让读者复述发生了什么；阅读扩展保留完整自然句和可读字号。
- [ ] 已逐张写明相对正文新增的信息，没有复制正文后讲得更短、更含糊。
- [ ] 图卡优先放结构、流程、对照、界面证据或完整案例，正文保持连贯叙述。
- [ ] 技术长文图片已按实际阅读位置插入章节中间，图片前说明观看重点，图片后有能独立理解的图注。
- [ ] 踩雷路线的每张图承担一个关键转变、真实证据或前后对照，没有把完整决策库做成流水时间轴。
- [ ] 已先列出可公开的真实截图、录屏、图表和产物图；能用真实画面说明的信息没有退回纯文字卡。
- [ ] 所有真实画面均通过发布安全检查，不含公司信息、身份信息、密钥、内网地址、本地路径或未公开内容。
- [ ] 错误案例优先展示真实的错误界面、旧/新差异、真实工作日志或具体代码操作；看完画面能一眼指出“哪里错、怎么改”，没有用无关网页或正文复述充数。
- [ ] 用户审稿反问若用于替陌生读者指出理解门槛，图片明确标注“读者会缺少什么信息”，不把反问画成 ColorC 本人不懂任务；正文不再逐字重复同一组坏句和原话。
- [ ] 已为每张图标明信息任务、素材来源和主版式；整组至少包含三种主版式。
- [ ] 相同主版式没有连续超过两张，也没有超过整组图卡的 40%；统一 DOS 主题没有被做成统一模板。
- [ ] 关键正文渲染字号不低于 42px，标题通常不低于 64px。
- [ ] 1080×1440、DOM 无越界、文字元素无意外相撞、语义断行自然、真实审阅页自然尺寸和手机可读性均已检查。
- [ ] 内容放不下时已经增卡、改用长文、拆成系列帖或明确改为阅读扩展，没有靠缩字、短语堆叠和删除语法成分解决。
- [ ] 完整图卡由 HTML/CSS 形成结构，生图模型只用于局部示意素材或自然圈画。
- [ ] 图卡沿用个人网站的 DOS 视觉主题；Reviewstage 继续使用中性界面。
- [ ] DOS 主题对齐已验收的 v13/v16 卡片：色板、右上页码、字体、线条和留白一致；没有后来新增的三圆点浏览器壳，也没有把所有卡强制成相同标题栏/页脚。
