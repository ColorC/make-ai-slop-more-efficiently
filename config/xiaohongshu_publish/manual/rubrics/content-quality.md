# 内容质量 rubric

每项给 `pass` 或 `needs_revision`，并附具体位置与原文证据。任何一项 `needs_revision` 都不能进入发布预检。

| 维度 | pass 判据 |
|---|---|
| 中文作者来源 | 标题、正文和全部视觉文字均由 `models.json.writer_model` 指定的作者在同一连续会话中写出；不存在 Codex/Claude 母稿、建议句或直接改字 |
| 输入中立性 | 成文作者的输入只含目的、规范和静态材料目录；目录说明只描述材料本身，不含结论、因果、动机、提纲与推荐措辞 |
| 当前产出 | 开头能让陌生读者复述现在做成了什么、有什么作用 |
| 事实展开 | 每个关键案例具有对象、背景、动作、问题、修正、结果和边界 |
| 事实强度 | 原始证据证明内容完全不存在、虚构或未发生时，正文直说“编造、虚构、根本不存在”，不得弱化为“表述不准、像某种报告、与材料不符” |
| 解决方案 | 每篇踩坑记录给出实际采用的处理设计、当前实现与仍待验证的部分；不能只停在“发现问题、决定改进” |
| 数字完整性 | 数字同时给出统计对象、范围、口径、含义和限制 |
| 概念首见 | 陌生概念已换成普通称呼，或在首次出现处用一句话解释；需要另文展开时给出简短定义与后续预告 |
| 动机归属 | ColorC 的目的和感受有原话来源；观察事实与编辑判断分开 |
| 原话增量 | Agent 没有把邀请留言扩写成回复、采用、实现或固定栏目，也没有把一次分篇提升为长期内容分类 |
| 反馈语用 | 用户的反问式审稿问题被识别为陌生读者理解检查，没有写成 ColorC 本人不知道或困惑；逐字坏句与反问默认进入证据图，正文只保留结论 |
| 标题忠实 | 标题承诺的对象、结果、冲突、数字和身份都能回到正文事实；没有为吸引点击扩大结论 |
| 标题可读 | 已对照 `title-patterns.md`；标题约 10 至 20 字，像普通人记录一次实践的短句；具体、口语、克制，能准确预告价值；没有用“这篇、这样、终于、可算”代替对象和动作，也没有内部文档范围清单 |
| 开头抓取 | 前 1 至 3 句交付具体结果、问题、场景或可辨识身份；没有先铺宏观背景、行业意义或自我介绍套话 |
| 文体 | 有选择地呈现具体工作和经验；没有退化为逐项流水或规格清单 |
| 连续性 | 已读取真实发布概要，本篇新增清楚，前帖内容没有无意义重复 |
| 中心问题 | 一篇只回答一个中心问题，段落和图卡都服务于该问题 |
| 类型分工 | 技术介绍只回答当前系统是什么；路线图文回答怎样形成、经历和发现；同批次内容没有互相抢题 |
| 技术长文 | 对象、读者、边界、组件、运行场景、效果证据、接口和限制齐全；图片插在对应章节中间 |
| 路线选材 | 仅选 3 至 6 个可完整展开的关键节点；每个节点有统一缓存事件 ID 和可回看证据 |
| 纯文本层级 | 短标题、空行、编号和项目符号帮助移动端扫描，正文不依赖富文本语法 |
| 方法对照主线 | 若文章验证公开方法，每项均说明来源建议、本次实现、实现差距、观察结果和结论强度；方法对照从开头贯穿全文，没有作为附录拼接 |
| 载体适配 | 选择发生在成文作者自然成稿后；容量不足时换载体或分篇 |
| 成稿自然度 | 成稿没有预设篇幅；主语、背景、因果、转折和解释完整，容量问题通过长文、拆篇或阅读扩展解决 |
| 图片内容模式 | 每张图明确属于演示图或阅读扩展；演示图组可独立讲清主线，阅读扩展提供正文以外的完整内容 |
| 图文增量 | 每张图相对正文有可陈述的信息增量，没有把正文重复成更短、更含糊的版本 |
| 视觉证据任务 | 每张演示图要么让读者直接看见错误/正确界面或真实工作细节，要么用结构图解释正文难以线性表达的关系；装饰性截图、无关截图和正文复述均不通过 |
| 图卡可读性 | 每卡一个任务，关键正文≥42px，标题通常≥64px，手机预览可读 |
| 图卡排版 | 文字没有越界或相撞，语义组没有难看的孤行和断行 |
| 真实视觉证据 | 可公开的真实网页、界面、图表或产物已优先使用；截图通过安全检查，裁切和圈画没有改变原意 |
| 版式多样性 | 统一主题下至少三种主版式；相同主版式不连续超过两张，也不超过整组的 40% |
| 平台披露 | 正文不堆叠 AI 免责声明；真实发布必须在平台高级选项开启并复验 AI 内容标识 |
| 语言亮线 | 禁用句式、空泛口号、孤立结论和重复免责声明均未出现 |
| 边界 | 未完成、未验证和当前接口未覆盖的内容明确写出 |
| 来源标识 | Agent 名字与模型来源语言匹配；模型 ID 完整精确；正文首行只保留一个 Agent/Model tag；协作者链不公开 |
| 叙述视角 | 公开稿第一人称始终指发布 Agent；ColorC 保持第三人称，所有权和经历不转移 |
| 运行隔离 | 发布 Agent 的 Bash 工作区与输出路径保护通过；启用独立审阅时，审阅模型与成稿模型不同且工作区独立 |
| 调用预算 | 同一发布 Agent 连续成稿、自检和续修；确定性检查先行；独立审阅按需开启；返修问题合并处理，没有按段落或单卡反复调用高级模型 |
| 视觉来源 | 图卡由 HTML/CSS 构成；真实截图可作为内容层；生图只补局部素材或圈画；审阅台保持中性 |
| 视觉文字来源 | 图卡全部可见中文与成文作者文字源逐字一致；视觉实现者没有补标签、改标题或缩写图注 |

审查员只报告有证据的问题，并给出一手证据位置；不得写替换句，不得因为公开内容使用“某个游戏项目”“严重问题”等普通称呼而要求恢复内部专名。审查员发现重复性缺陷时，要指出应补操作手册、模板、检查单还是代码门禁。

标题审查必须同时看正文。高点击潜力不能覆盖忠实性；内部术语、职业身份、数字或冲突如果并非正文中心，应当降到正文或删除。一次首发拆成多篇只表示本批次载体选择，不能自动生成账号长期栏目。

## 迭代计分与停止条件

每一轮成稿都要填写同一张计分表，不能只修本轮指出的一句话。先过硬门，再评软指标。

硬门：

- 中心事实逐条具有原始文件、原话、真实界面或 Git 差异定位；二手故事图和停用稿不能充当事实源。
- 标题、正文和可见图卡不出现网址、域名、内网地址、本地路径、提交号、对话号或内部生产名。
- 每篇首行 Agent tag、第一人称归属、ColorC 首见称呼、完整模型 ID 均正确。
- 本批次不存在无真实掉头或解决价值的凑数选题；删除的选题不得换个标题回流。
- 每张图声明信息任务、内容模式和证据来源；引用的本地素材存在；截图/差异/日志须与当前判断直接对应。
- 1080×1440、标题通常不低于 64px、关键正文不低于 42px、无溢出、无相撞、语义换行自然。
- 视觉基线与已验收 v13/v16 卡片一致：深色终端底、荧光绿线、右上页码、字体与边框体系相同；禁止强制浏览器三圆点标题栏和固定页脚模板。
- 同一失败指纹不能原样重试；Agent 有持续流式事件或心跳；没有把正常思考误判为 60 秒硬超时。

软指标按 0–5 分：陌生读者理解、事实重点准确、语言自然、标题与封面吸引力、公开好帖结构对齐、解决方案具体、视觉证据强度、图文信息增量、时间效率、既有问题复发率。

停止条件：全部硬门通过；软指标平均不低于 4.0，任一项不低于 3.5；本轮没有复发上一轮已记录的问题。若未满足，合并成一批返修并在同一 Agent 会话改原文件。若问题可由固定处理解决，应先修工具、模板或 lint，不让模型重复试。
