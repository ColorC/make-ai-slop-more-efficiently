# 小红书标题参考：克制、具体、谦逊

本页是发布 Agent 每次成稿都要读取的标题参考；任务明确启用独立审阅时，审阅 Agent 也读取。它来自 2026-07-14 的小红书 AI 实践、独立开发、自动化工具与开发复盘标题调研，并结合本账号首批发布反馈整理。它约束表达方式，不提供可机械套用的标题公式。

## 先满足的四件事

1. 标题直接写出对象或动作，让读者不看正文也知道大致在讲什么。
2. 用普通人口吻，允许“记录一下”“我试着”“第一次”“目前”这类克制表达。
3. 数字、结果、身份、冲突只有在正文有直接证据且确实构成重点时才使用。
4. 标题承担一次邀请阅读，不承担项目摘要、架构目录或营销口号。

## 本账号适合的基础模式

- 账号介绍：`记录一下，我怎样把 AI 用进日常工作`
- 工具介绍：`我试着做了一条小红书发布流程`
- 当前进展：`目前这条 AI 发布流程能做什么`
- 开发记录：`第一次认真整理我的 AI 工具和工作流`
- 踩坑复盘：`做 AI 发布流程时踩过的几个坑`
- 单点经验：`给 AI 写开发日志，我先解决了这几个问题`

这些是语气与结构示例。写作 Agent 必须根据本篇事实重新起题，禁止照抄为固定栏目。

## 直接淘汰的标题

- 空泛指代：`你现在看的这篇帖子，是这样写出来的`
- 只有发布情绪：`可算是发出来了`、`终于做出来了`
- 寒暄开场：`你好，这里记录……`、`大家好，我是……`
- 内部文档：`发布管线架构说明`、`发布管线与三个修正案例`
- 夸张承诺：`一键搞定`、`保姆级`、`全网最全`、`效率翻倍`
- 无证据数字：为了吸引点击临时添加天数、百分比、模块数或“第 N 次”

## 审阅方法

发布 Agent 自检时回答；启用独立审阅时，审阅 Agent 再回答：

- 删除“这篇、这样、终于、可算”后，标题里还剩下具体对象和动作吗？
- 标题是否比正文更夸张、更确定，或暗示了正文没有证明的结果？
- 这句话像普通人记录一次实践，还是像内部材料名称、媒体通稿或运营模板？
- 若换成更朴素的说法，信息量是否完全不受损？若是，采用朴素版本。
